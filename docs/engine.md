# THE ENGINE

**What the hardware gives you, what it costs, and the traps that have already caught this project.**

`vision.md` is the design bible and it is **engine-independent on purpose** — the argument does not change because the cartridge did. This is the other half: the facts about the Game Boy Advance and about `pokefirered` that we have had to learn, almost all of them by breaking something first.

*Prose here is authored. Every **number** is written by `tools/gbabudget.py --write`, because a figure in prose drifts the moment anything moves and nobody notices until a build stops.*

```sh
python3 tools/gbabudget.py           # report
python3 tools/gbabudget.py --write   # and update the tables below
```

## 1. The memory, and which one people mean by "storage"

**Three unrelated budgets, and only one of them is large.** When someone says a GBA cartridge holds a lot, they mean **ROM** — the cartridge itself, read-only, and the one this project spends freely. **EWRAM** and **IWRAM** are the working memory the game runs in, and both are nearly full *in stock pokefirered*, before we add anything.

## 2. Where a variable lands, which is not where you would guess

**This is the single most useful fact in this document.**

| you write | it lands in | notes |
|---|---|---|
| `EWRAM_DATA int x;` | **EWRAM** | the scarce one — about a kilobyte free |
| `static int x;` (uninitialised) | **IWRAM**, as `COMMON` | the *other* scarce one — about three kilobytes free |
| `static int x = 7;` | **`.data`, which the link script DISCARDS** | ***does not link.*** See trap 2 |
| `const struct Thing x[] = {...}` | **ROM** | free, effectively. Sixteen megabytes spare |
| `AllocZeroed(n)` | **the heap**, at runtime | costs neither budget. **Prefer this** |

***So the rule is short: content goes in ROM, screens allocate from the heap, and a new static of any kind is a decision rather than a convenience.***

**`gHeap` is the biggest single object in EWRAM** and it is not waste — it is the pool every transient screen carves out of, and it is why the Bag, the Index and the STREAM's menu cost nothing permanent. *When something is needed only while a screen is open, `AllocZeroed` it and `Free` it; the numbers above will not move.*

**Shrinking `HEAP_SIZE` to buy static space is a last resort**, and the reason is the failure mode rather than the size: **an EWRAM overflow is a link error, loud and immediate; a heap exhaustion is a runtime allocation that returns null**, on a screen, on someone's cartridge. *Trading the first for the second is a bad trade even when the arithmetic works.*

## 3. Every fixed width, and what we actually ship in it

**A name in this game lives in a fixed-size array, and the array declares the limit — not the constant beside it.** *`gSpeciesNames` is `[POKEMON_NAME_LENGTH + 1]`, so that constant IS the character count; `ItemInfo`'s name is `[ITEM_NAME_LENGTH]`, so there it is one more than the count.* **`gbabudget.py` reads the declaration** so nobody has to remember which family a surface belongs to.

*The tables below are generated with the memory figures — see section 1's markers.*

**Overflowing one of these is a compile error that does not name the string.** agbcc reports it as *"excess elements in array initializer"*, and this build turns warnings into errors, so what you actually see is a bare `Error 1` a long way from the edit.

**A pane is different: it has no declared width at all.** *So the width is read out of vanilla instead* — **vanilla never overflows its own window, so the widest line it ships in a pane is a demonstrated safe width.** ***That is a floor, not a ceiling.*** *Being wider than it is a thing to look at, not automatically a bug — the item box turned out to be 198px and the Index line 234px this way, and both have held.*

## 4. The traps, in the order they cost us time

Every one of these has happened here, and each is listed by its **symptom**, because the symptom is what you will actually be looking at.

### 1. A clean-looking build that produced the old ROM

***Symptom:*** *`make … | grep -i "error:"` prints nothing and the game has not changed.*

**agbcc emits its diagnostics as `warning:` lines and then fails with a bare `Error 1`.** *Filtering for `error:` reports a clean build while the binary silently stays as it was.* **This has caused two bugs in this project.** ***Check the exit code, never the output:***

```sh
make -C engineGba firered_debug -j8 >/dev/null 2>&1; echo "exit=$?"
```

### 2. `defined in discarded section '.data'`

***Symptom:*** *a link error naming a section, never the variable.*

**The link script has no `.data` output section**, so any *initialised* file-scope static is discarded and every reference to it dangles. **Declare it uninitialised and let zero mean the default** — which is usually the state every other path is already in anyway.

### 3. A `#if` that works in C and does nothing in a script

***Symptom:*** *debug-only text turning up in the release ROM, or a `.if` that never fires.*

**`-D` flags reach the C preprocessor; `.inc` scripts go to the assembler**, which sees `--defsym` instead. `DAEMONS_DEBUG` is passed **both** ways now, so `#if DAEMONS_DEBUG` and `.if DAEMONS_DEBUG == 1` both work. ***Verify by grepping the ROMs, not by reading the Makefile:***

```sh
python3 tools/gbastr.py "some debug string"
```

### 4. Edits that exist only on one machine

***Symptom:*** *it works here, and a fresh clone builds vanilla.*

**`json_data_rules.mk` generates seven headers and every one is gitignored** — `items.h`, `region_map_entry_strings.h`, `region_map_entries.h`, `wild_encounters.h`, `heal_locations.h` and two constants files. ***Write the `.json`, never the header.*** *Sixteen town names once existed in exactly one working build this way.*

### 5. A substitution that misses every word at the start of a line

***Symptom:*** *a rename that is 90% applied, and the survivors all sit after a `\n`.*

**An escape is two characters and the first is a letter.** *In `\nPOKéMON` the `n` sits against the `P`, so `\b` finds **no word boundary** and the word is invisible to any pattern looking for it.* **This has hidden substitutions in six separate tools here.** ***Flatten before you match, and re-run every tool until it reports nothing*** — that is what caught all six.

### 6. A prose pass rewriting a name table

***Symptom:*** *none. It compiles, it ships, and the name is subtly wrong.*

**The ability `OWN TEMPO` was authored `NO THRASH`.** *Renaming the move `THRASH` to `BUSY WAIT` turned it into `NO BUSY WAIT` — twelve characters of twelve, so nothing complained, and it shipped.* **Three more went the same way, one of them the line in the SCHOOL whose entire job is teaching the type chart.**

***The rule was written down and only half enforced:*** **name tables are authored and prose is swept.** *`port_vocab`'s `FIXED` list was a **width** check wearing a name-protection label — it refused a rename that overflowed and accepted one that fitted.* **Now a span matching any `FIXED` pattern is skipped entirely**, whatever file it is in, and the width check sits underneath as belt and braces.

**Two related guards, same root:** *the eighteen **type names** are withheld from the word map completely* (the chart is the argument, and `GROWTH` is also a move that was renamed), and *a **phrase's output** is stashed so the word pass cannot sweep it again* (`MIRACLE SEED` → `GROWTH GAIN` → `SCALE UP GAIN`, on the prize board).

### 7. A guard that has outlived its reason

***Symptom:*** *a rename that simply does not happen, with nothing reported.*

**`SMOKE BALL` and `LIGHT BALL` were held out of the sweep because `BALL` is the capture device and neither of these is one.** *Once both had names of their own, the guard was the only thing stopping the rename.* ***A stale exception is indistinguishable from a missed substitution***, so exceptions get a comment naming what would have to change for them to be removed.

### 8. A substitution that grows every time you run it

***Symptom:*** *`DAEMONSSSSSSS`.*

**A rename whose OUTPUT still contains its KEY matches itself on the next run**, and this project's own instruction is *re-run every tool until it reports nothing* — so a non-idempotent rule is not a warning, it is a corruption engine with a crank on it. `"to get rare DAEMON"` → `"to get rare DAEMONS"` added one letter per run across seven files.

**Stashing the output protects ONE pass and cannot protect the next**, because by then the output is the file's own text. ***`port_vocab` refuses any pair where `key in value` now***, rather than warning.

### 9. A file that empties itself

***Symptom:*** *a file is zero bytes and nothing errored.*

```python
open(P, 'w').write(open(P).read().replace(a, b))     # DESTROYS P
```

**Python evaluates the object before the argument**, so the `'w'` handle is created — *and truncates the file* — **before the read on the right-hand side ever runs.** *It then writes the empty string it just read.* **This has emptied `docs/README.md` three times in two days**, and each time it was quiet: the file is not in any build, so nothing breaks until somebody looks.

***Read into a variable, assert it is not empty, then open for writing.*** *And the check that watches that surface has to fail on an absent row rather than agree with it — an empty file agrees with everything.*

### 10. Believing the `.gba` file size

***Symptom:*** *ROM usage that never moves.*

**`objcopy --pad-to 0x9000000` pads every build to a flat sixteen megabytes**, so the file size is the same whatever the cartridge holds. *The real figure is the linker's high-water mark* — which is what `gbabudget.py` reconstructs out of the map, and it agrees with `--print-memory-usage` to the byte.

## 5. Two habits worth keeping

**Derive, don't assert.** *Every tool in `tools/` that reads the game's own data has needed no revision; every one that encoded a fact by hand has.* **When the model or the game looks confused, grep our own data before blaming either.**

**Measure the whole table, not the diff.** *Two broken item descriptions — a scale that shone "a HALT pink", a spoon that boosted "CONSTRUE-type moves" — had been shipping for days.* **Neither was in any diff anybody was reading.** *They turned up the moment something rewrote the file end to end.*
